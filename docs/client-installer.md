# Client installer

The installer prepares a client PC for nodehub support. It is a PowerShell script generated by the
dashboard (**+ Add machine → Download installer**) from the template
[`installer/install-client.ps1`](../installer/install-client.ps1), with the installation's secrets
filled in:

| Placeholder | Filled with |
|---|---|
| `__NODEHUB_AUTHKEY__` | `TAILSCALE_AUTHKEY` |
| `__NODEHUB_PUBKEYS__` | Every key in `public-keys/*.pub` |
| `__NODEHUB_CLIENT_TAG__` | `CLIENT_TAG` |

## Running it

On the client PC: **right-click → Run with PowerShell**, accept the administrator prompt. It
elevates itself and needs no input. A log is written to `C:\ProgramData\nodehub\install.log`.

Unattended (e.g. over an existing SSH or RMM session, already elevated):

```powershell
powershell -ExecutionPolicy Bypass -File nodehub-install.ps1 -NoPause
```

## What it changes

| Step | Change |
|---|---|
| **1. Tailscale** | Installs Tailscale (unattended mode, survives sign-outs) if missing, after checking that the downloaded MSI is validly signed by *Tailscale Inc.* (otherwise it stops without installing anything), and joins the tailnet with the auth key, which applies the client tag. The machine name is the Windows computer name in lowercase. **If the machine is already on the tailnet with the client tag, this step changes nothing** (so its name and history stay the same). |
| **2. `nodehub` user** | Creates a local user `nodehub` in the Administrators group (by SID, any Windows language), with a random password nobody knows, never expiring, hidden from the sign-in screen. Re-running resets the password to a new random one. |
| **3. OpenSSH Server** | Installs the Windows *OpenSSH Server* capability, starts `sshd` automatically, sets PowerShell as the default shell, disables password authentication, and **adds** the technicians' public keys to `C:\ProgramData\ssh\administrators_authorized_keys` (existing keys are kept; duplicates are skipped). |
| **4. Firewall** | Disables the default *OpenSSH-Server-In-TCP* rule and creates `nodehub-SSH`: port 22 only from `100.64.0.0/10` (the Tailscale range). |
| **5. Clean-up** | Deletes itself, because it contains the Tailscale auth key. |

The messages on the client PC are in the **team language** (English or Portuguese), set by an admin in the dashboard.

It is safe to run again: use that to add a new technician's key to a machine that is already set up.

## Requirements and known limitations

- Windows 10 1809+ / Server 2019+, run as administrator.
- Internet access to download Tailscale and the OpenSSH capability. **OpenSSH comes from Windows
  Update:** on PCs where Windows Update is blocked or managed by WSUS, this step can fail (the error
  is shown and logged). Allow the capability temporarily, or install
  [Win32-OpenSSH](https://github.com/PowerShell/Win32-OpenSSH/releases) manually and re-run.
- If the PC already uses Tailscale with **another account** (e.g. the client's own), joining fails.
  A device can only be in one tailnet at a time.
- Browsers may warn that a `.ps1` download "may be harmful": choose *Keep*.

## Removing access

To stop supporting a machine:

1. In the dashboard: **⋯ → Remove** (keeps its history).
2. In the Tailscale admin console: **Machines → … → Remove** the device.
3. On the PC (as administrator), optionally undo the installer:
   ```powershell
   Remove-LocalUser nodehub
   Remove-NetFirewallRule -Name nodehub-SSH
   # Remove the technicians' lines from C:\ProgramData\ssh\administrators_authorized_keys
   # Optionally: Stop-Service sshd; Set-Service sshd -StartupType Disabled
   # Optionally: uninstall Tailscale from Apps & features
   ```

An automatic uninstaller is on the [roadmap](roadmap.md).
